# 单位视觉改造报告

> 依据：《纯代码单位视觉设计与建模Prompt.md》。全部单位视觉为纯代码程序化拼装（Primitives + 程序化 Mesh），零外部美术资源。
> 范围：人类/不死双阵营 5 类单位（工人/步兵/远程/骑兵/英雄）+ 通用战斗特效系统 + 编辑器质量检查工具。

## 2. 新增类/方法/字段（要点）

- `Models.Units.BuildUnit(Transform, Team, UnitDef)`：单位总入口，按 `hero / worker / kind` 分派；构建完成后快照动画基准（`armRHome`/`soulCoreBase`/`floatBase`），动画全部基于绝对值计算，**绝不每帧累加**。
- `UnitVfx.PlayAttackStartEffect / PlayHitEffect / PlayDeathEffect`：静态方法 + 静态对象池（上限 80，LRU 回收），不随单位 Destroy 丢失。
- `BodyRig` 新挂点：`armR/armL`（持械手）、`projectileOrigin`（弹道起点：弓口/法杖晶体）、`auraOrigin`（英雄光环）、`soulCore`（巫妖魂核）、`floatingParts[]`（浮游碎片）、`horseLegs`（坐骑腿）、`thrustAttack`（突刺动画标记）。
- `Unit.Anim(float moving, float dt)`：躯干起伏 `p.y = (有腿 ? size*.75 : 0) + |sin|*.05*blend`；枪盾步兵走 armRHome 基准 +Z 突刺，其余挥砍；prefab 单位 `rig == null` 时所有路径早退（已逐处判空，防 NRE）。

## 3. 每单位视觉差异（相对旧版）

| 单位 | 旧版 | 新版 |
|---|---|---|
| 农夫/侍僧 | 色块胶囊 + 锄头 | 分节躯干/头/双臂/双腿，人类布衣束腰、不死破碎袍摆；手持工具；行走摆臂+躯干起伏 |

| 远程 | 方块 + 箭 | 人类：皮甲+长弓（弓口挂点为弹道起点）；不死：骨弓+兜帽；张弓/拉弦动画 |
| 骑兵 | 大块 | 马体（躯干/颈/头/四腿/尾/鞍具）+ 骑手；行走四腿交替蹬地；骑枪（人类）/腐化骑枪（不死） |
| 人类英雄 骑士团长 | 大骑士 | 专属构建：**金色全身铠甲 + 盔缨 + 圣辉骑枪 + 马铠**；冲锋突刺动画；地面圣光光环旋转 |
| 不死英雄 霜骨巫妖 | 大射手 | 专属构建：**细长头骨 + 悬浮骨冠 + 破碎法袍（无腿悬浮）+ 冰晶法杖**；魂核脉动、骨片浮游环绕 |

英雄与普通兵种完全独立构建（`BuildUnit` 中 `def.hero` 优先走专属分支，**不再叠加**普通兵种构建——修复了旧逻辑多出一杆不能动的长矛的 bug）。

## 4. 特效系统与画质档位

- 三档：`Off`（全关）/ `Low`（半透明闪缩，无粒子）/ `High`（加粒子、光环、地面法阵）。
- 攻击前摇：近战武器后摆、远程弓/杖充能——给玩家反应窗口。
- 受击：白闪 + 微缩；死亡：变暗下沉 + 尸体残留。
- 静态池上限 80 个活动特效，超出自动回收最旧；`Update` 内 `Vel()` 判空防 NRE。

## 5. 编辑器质量检查工具

菜单 **工具 → Eresoth RTS → 视觉模型质量检查**：预览任意单位（含双英雄）、统计 Renderer/Tri/Material 数、输出 budget 超支警告；**生成报告到 `ProjectBook/VisualModelQualityReport.md`**。另有同菜单预览窗口可实时查看动画。

## 6. 性能估算（以实跑检查器报告为准）

- 普通单位约 8–14 个 Renderer、<1.5k tris；英雄约 20–30 个 Renderer、<3k tris。
- 同屏 100 单位 + 80 特效池，估算 <2k draw call 等效（无光照实时代码材质，CPU 拼装只在出生时一次）。
- 权威数字请运行检查器菜单，以 `ProjectBook/VisualModelQualityReport.md` 为准。

## 7. 管线兼容性 / 回滚

- 纯代码路径：`Unit.Spawn` / `Building.Spawn` 中 `def.prefab == null` 时走 `Models.BuildUnit/BuildBuilding`；配置 ScriptableObject 挂 prefab 即可整体替换为美术资产，互不影响。
- 回滚：删除上述新增文件、还原 `Unit.cs`/`Common.cs`/`Models.Gfx.cs` 的合并片段即可；旧视觉路径已完全被新入口替代，无中间态。

## 8. 已知限制 / 验证情况

- Unity 编辑器占用期间无法批处理跑检查器，renderer 数为代码估算（见第 6 节）。
- 已验证：`compile_check.sh`（Roslyn 全量编译）通过；动画不变量经代码走查（快照绝对值、rig 判空、弹道起点回退逻辑）。
- 建议人工过一遍：训练 each 兵种观察行走/攻击/死亡动画，开一场对战看英雄光环与死亡特效。
