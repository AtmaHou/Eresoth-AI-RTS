# 第一阶段（S0+S1）代码修改说明

> 修改后的完整项目在 `Eresoth-AI-RTS/` 目录，直接覆盖原项目同名文件即可。
> 所有新代码位于 `Assets/Scripts/Command/`，namespace 仍为 `Eresoth`。
> 新增的 9 个 .cs 文件没有 .meta——Unity 首次打开时会自动生成，无需处理。

## 新增文件（Command/）

| 文件 | 职责 |
|---|---|
| `GameEventBus.cs` | 事件总线：发布/订阅 + 200 条环形日志，条件触发/战报/态势摘要共用 |
| `SemanticMap.cs` | 语义点注册表：稳定 ID + 中文别名消歧（"东矿"→敌方东侧魔法矿，"家门口"→己方主基地） |
| `SemanticMapRegistrar.cs` | BuildWorld 末尾按本局实际布局注册语义点（含中央富集矿、撤退点、敌方前线动态点） |
| `Force.cs` | 军团对象：构成/血量/质心统计、stance、rallyPoint、当前军令 |
| `ForceManager.cs` | 军团管理：创建/编组/查找，AutoForm 自动编两军团，新训练单位自动入编，每 2s 更新敌方前线语义点 |
| `Order.cs` | 军令对象：8 种动作白名单、生命周期状态机、触发条件、玩家原话快照 |
| `OrderDispatcher.cs` | 军令调度：校验→仲裁（优先级覆盖）→生效，命令日志（100 条），ExplainForce 回答"为什么没执行" |
| `ForceController.cs` | 战术执行体：0.25s tick 驱动 8 种动作；残血撤退/追击上限/条件触发/目标丢失重规划；事件订阅紧急回防（≤300ms 不等 tick） |
| `DebugCommandRunner.cs` | 硬编码 JSON 驱动入口：DTO 与未来 CommandSchema 同构；F1~F8 示例军令、F10 自动编组 |

## 试玩流程（验收路径）

1. 正常开局，先发展生产出一些战斗单位。
2. 按 **F10** 自动编组（战斗单位交替编入一军团/二军团）。
3. 按 **F9** 打开指挥面板观察。
4. 试示例军令：
   - **F1** 一军团防守主基地（追击不出 15 格）
   - **F2** 二军团推进东矿，发现敌方主力（≥8 战斗单位）自动撤到撤退点 ← 传播点 #2 雏形
   - **F3** 一军团集火（英雄优先）
   - **F6** 二军团谨慎推进敌方前线，伤亡过半自动撤
   - **F7** 一军团的骑兵单独去骚扰敌方西矿（unit_filter）
5. 让 AI 打一下你的主基地 → 最近军团立即自动回防（紧急通道）。
6. 右键手动指挥某个单位 → 8 秒内它不听军团调度，之后回归。

## 设计要点备忘

- **手动接管**：`manualOverrideUntil`（8s），防止"AI 抢鼠标"。
- **优先级**：系统紧急回防=90 > 玩家军令=50；同军团新命令优先级 ≥ 现役命令则覆盖（状态 Overridden，日志可查）。
- **失败可解释**：所有拒绝/失败都有中文 failReason，F9 面板和 Toast 直接可见。
- **DTO 与未来 CommandSchema 同构**：S4 接 OpenAI 兼容 API 时只需把"F 键 → 模型输出 JSON"接进 `DebugCommandRunner.Run()`，执行链路全部复用。

## 已知边界（本阶段不做，属 S2+）

- 经济/生产/科技的自然语言计划（S2）。
- 战争迷雾/可见性过滤（S3，当前"敌方前线"质心等于开全图）。
- 残血撤退后归队逻辑依赖 rallyPoint，军团全员撤退时 rallyPoint 已随质心移动——极端情况下撤退距离偏短，后续可改为固定撤退点。
- AutoForm 只分两团；动态拆分/合并（命令 9）在 F6 阶段。
