# D2 阶段修改说明（指挥台交互优化与指令缓存）

> 覆盖项目 `EresothRTS/`，直接覆盖同名文件即可。
> 新增 .cs 无 .meta，Unity 首次打开自动生成。

## 这一阶段做了什么

**指挥台从"能用"升级为"好用"**：修掉中文输入与连通性测试两个硬伤，原始输出可滚动，新增"玩家标记 → 文件缓存 → 命中拦截"的降延迟链路，常用指令可在开始界面配置。LLM 侧新增推理模式（thinking）开关，兼容 kimi-k2.6 这类隐性推理模型。

### Bug 修复

1. **连通性测试误报"已连通但返回异常"**：`kimi-k2.6` 实为推理模型，测试请求 `max_tokens:16` 的预算被 `reasoning_content` 占光（`finish_reason:"length"`），正文为空被判异常。修复：未判定为推理的模型先发 16 token 小预算探针测延迟，发现被截断（`finish_reason=length`）自动放大到 512 重试一次，不再依赖模型名字判断。
2. **命令输入框无法输入中文**：IMGUI 的 `GUI.TextField` 在编辑器 Game 视图及部分 Windows 构建收不到 IME 合成串。新增 `ImeTextField` 手动管理输入（合成串实时预览、选词上屏写入），命令输入框与常用指令输入均已切换。

### 新增文件（Command/）

| 文件 | 职责 |
|---|---|
| `ImeTextField.cs` | 中文输入法支持的最简输入框：合成串（`Input.compositionString`）实时拼在末尾显示，选词提交写入；支持末尾追加/退格/Ctrl+V 粘贴；合成中吞掉按键防止误触发发送与镜头快捷键 |
| `CommandCache.cs` | 指令缓存：玩家标记"成功"的 `输入文本 → 格式化指令 JSON` 落盘项目根 `command_cache.json`（pretty JSON 可手编辑，上限 500 条，带时间戳与命中计数）；命中规则为 Trim 后完全一致，命中直接回放、跳过 LLM |
| `FavoriteCommands.cs` | 常用指令列表：开始界面配置，落盘项目根 `favorite_commands.json`，上限 12 条 |

### 新增能力

**① 指令缓存（省延迟省 token）**
- 每条执行了格式化指令的参谋回复带 ✔/✘ 小按钮：✔ 成功 → 写入/更新缓存；✘ 失败 → 移除同条目，防止错误指令被拦截。
- 下次同输入发送时直接回放缓存结果，参谋回复带"［缓存命中］"，不构建 digest、不调 LLM，`command_log.jsonl` 记 `cache_hit`。
- 离线兜底解析的结果同样可标记入缓存（序列化 `CommandRequest` 回放，行为一致）。

**② 常用指令（开始界面配置）**
- 菜单左上角"常用指令：N 条"按钮打开配置区，与 LLM 配置共用面板底部、互斥展开。三个来源：**手动输入**（中文可用）、**默认样例**（点击即加）、**从指令缓存勾选**（按命中次数排序）。
- 对局内指挥台"高频命令"区优先展示常用指令，点击即填入输入框；未配置时保持 D1 默认样例。

**③ 推理模式开关（LLM 配置）**
- 配置新增 `thinking` 字段（`llm_config.json` / F10 面板"模式"开关均可）。生效规则：`用户开关 ‖ 名字带 thinking/reason`。名字可识别的始终强制按推理对待。
- 开启后：解析调用 temperature=1、不挂 `response_format`、超时 60s；连通性测试直接用 512 token 预算（跳过小预算探针）。
- 背景：thinking 是模型服务端行为，客户端无法对 kimi-k2.6 关闭推理，只能适配（调大预算/放宽超时）；要非推理行为需换非推理型号（如普通 kimi-k2）。

**④ 原始输出可滚动**
- "查看原始输出"展开后从"封顶 6 行"改为滚动区（可视区封顶 148px，全文铺开，滚轮/拖动查看）。

### 对现有文件的改动

- `Command/LlmClient.cs`：测试请求被截断自动放大重试；`LlmConfig` 新增 `thinking` 字段；`GetConfig/SaveLocal/TestConnection` 签名带 thinking；`PickTemperature/SupportsJsonMode` 参数化推理判定。
- `Command/CommandConsole.cs`：输入框换 `ImeTextField`；`ChatMsg` 扩展（playerText/actionJson/feedback/rawScroll）；Send 前查缓存拦截；✔/✘ 反馈按钮；原始输出滚动区；高频命令接入常用指令；缓存命中日志写 null 请求现场避免误导复盘。
- `GameHUD.cs`：开始界面"常用指令"入口与配置面板（与 LLM 面板互斥）；`DrawIntro` 面板高度随抽屉切换。
- `.gitignore`：新增 `command_cache.json`、`favorite_commands.json`（本机运行数据不入库）。
- `体验验证指南.md` / `llm_config.template.json`：补 `thinking` 字段说明。

## 上手步骤

1. 打开项目进开始界面，右上角 **LLM：未配置** → 填 `base_url/api_key/model`（如 `kimi-k2.6`），把**模式**切到"推理（thinking）：开"，点**测试连通性**（应一次通过，3~5s），保存到本机。
2. **常用指令：0 条** → 手动输入几条习惯打法，或从缓存/样例添加，保存。
3. 开局后指挥台打一条指令，例如"全军撤退"。参谋回复后点右上角 **✔**（已存指令缓存）。
4. 再发一次"全军撤退"——应立即返回并带"［缓存命中］"，无 LLM 延迟。
5. 点开任意回复的"查看原始输出"，滚轮可翻全文。

## 已知边界

- **ImeTextField 只支持末尾追加/退格/粘贴**，不支持光标定位与中间插入；命令输入场景够用，富文本编辑勿用。
- **缓存回放不感知战局**：军团名等引用是标记那一刻的快照，跨局/军团改名后回放可能被拒（军令被拒会照常提示）。标记时留意。
- **缓存匹配是精确匹配**（Trim 后完全一致），"同义不同文"不命中——这正是交给 LLM 泛化的部分。
- 中文 IME 各输入法行为有差异，编辑器 Game 视图已验证思路可行，如个别输入法异常需按实际再调。
- 命中计数每 5 次才落盘一次（降低写文件频率），立即关游戏可能丢掉最近几次计数。
