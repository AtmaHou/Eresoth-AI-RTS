## 一、项目概述

### 1.1 项目愿景

传统 RTS 的门槛与乐趣衰减，核心矛盾在于：**战略决策的乐趣被 APM（每分钟操作数）碾压**。本项目的核心命题是把"操作层"交给 AI 执行体，把"决策层"还给玩家——玩家像真正的指挥官一样，用自然语言（文字/语音）下达意图，由大模型解析为结构化军令，再由本地战术 AI 完成微操执行。

### 1.2 目标用户

| 用户层 | 画像 | 对应模式 |
|---|---|---|
| RTS 老玩家 | 怀念星际/魔兽但手速退化 | 主线模式、双人对战 |
| 策略/卡牌玩家 | 喜欢构筑与博弈，厌恶操作 | 锦囊模式（Prompt 对战） |
| AI 爱好者 | 想体验"指挥 AI"与"调教 AI" | 锦囊模式、AI 将领模式 |
| 休闲玩家 | 单机人机、看电子斗蛐蛐 | 人机对战、观战模式 |

### 1.3 产品差异化

1. **指挥链分层**：玩家 → LLM 参谋 → 战术执行 AI → 单位，每一层职责清晰，操作负担逐层递减。
2. **Prompt 即战力**：锦囊模式让"写策略的能力"本身成为竞技点，形成全新竞技维度与 UGC 生态。
3. **语音多线**：语音调度支线军团，解决 RTS 多线操作的核心痛点。
4. **AI 指挥科技树**：科技强度与 AI 能力挂钩（解锁更深的指挥层级、更多的并行指令槽），而非传统的数值叠加。

## 二、世界观设定（中古魔幻）

### 2.1 背景梗概

**大陆：厄瑞索斯（Eresoth）。** 旧历 1047 年，"缄默瘟疫"席卷北境，死者不寐。人类诸王国退守圣辉山脉以南，依靠神木林地与魔法矿脉维持最后的防线；而在北方冻土，亡灵君王"低语者"将战死者的躯壳重新立起，铸成不沉的军团。

两大阵营争夺的不仅是领土，更是**魔法矿脉**——它既是施法与亡灵苏醒的能量源，也是大封印术式（人类）与亡者升华仪式（不死）的共同钥匙。

### 2.2 双种族设定

#### 人类 · 圣辉联盟（The Radiant Concord）
- **风格**：秩序、工事、神术与纪律。单位造价中等，防御与阵型加成强。
- **基调**：中世纪王国军团 + 圣光神术。建筑可加固、驻防。
- **英雄叙事**：骑士团长、皇家法师、教会审判官。

#### 不死 · 低语军团（The Whispering Legion）
- **风格**：数量、消耗、复苏与侵蚀。单位廉价但脆弱，可从战场尸骸中复苏补充。
- **基调**：亡灵天灾。核心机制"尸骸回收"——阵亡单位（敌我皆可）留下尸骸，可被亡灵巫师唤醒。
  > 实现状态（Phase 1 Demo）：V1.2 起暂移除——为简化 AI 与克制体系，Demo 改为"工人 + 步/弓/骑"三兵种循环克制，
  > 尸骸回收与亡灵巫师留待后续版本恢复。
- **英雄叙事**：亡灵君王、白骨祭司、缚魂者。

> 设计注：双种族先做"非对称但镜像可读"的平衡框架——人类强在阵地与续航，不死强在换血与滚雪球，保证对战博弈深度。

## 三、基础系统设计

### 3.1 资源系统（双资源）

| 资源 | 采集方式 | 主要用途 | 设计意图 |
|---|---|---|---|
| **魔法矿（Mana Crystal）** | 工人采集矿脉，矿点有限且可枯竭 | 建筑建造、兵种训练、科技 | 当前版本的主要经济资源，推动分矿和前线争夺 |
| **木头（Timber）** | 工人采集树林，资源点可枯竭 | 辅助建筑和部分训练 | 次要经济资源，维持双资源决策 |

- 资源点分布采用"主矿安全、中央富集分矿暴露"的经典布局，资源收集站作为远端交付点，保证骚扰与扩张博弈。
- 魔法矿同时是**AI 指令系统的燃料**（见 5.4），使经济决策与指挥能力挂钩。

### 3.2 兵种设计（每族 5 种，共 10 种）

#### 人类 · 圣辉联盟

| 兵种 | 定位 | 造价（木/矿） | 克制关系 | 特色技能 |
|---|---|---|---|---|
| 征召民兵 | 基础近战/可采集 | 40/0 | 克制：骷髅海（单体质量） | 可切换采集/作战形态 |
| 长弓手 | 远程输出 | 50/10 | 克制：轻甲、食尸鬼 | 火箭齐射（小 AoE） |
| 重甲骑士 | 突击/坦克 | 90/30 | 克制：远程阵地 | 冲锋（破阵+眩晕） |
| 牧师 | 辅助 | 60/40 | 克制：不死全族（圣光特攻） | 治疗、驱散诅咒 |
| 狮鹫骑士 | 空中/高造价 | 120/80 | 克制：地面慢速部队 | 空袭俯冲，被弓箭手克制 |

#### 不死 · 低语军团

| 兵种 | 定位 | 造价（木/矿） | 克制关系 | 特色技能 |
|---|---|---|---|---|
| 骷髅兵 | 炮灰/量产 | 25/0 | 克制：以量换远程阵地 | 尸骸复苏（死后 30% 概率原地爬起一次） |
| 食尸鬼 | 近战/可采集 | 45/5 | 克制：法师、牧师 | 啃食回复生命 |
| 亡灵巫师 | 施法/召唤 | 70/50 | 克制：重甲单体 | 尸骸唤醒（把战场尸骸变骷髅）、诅咒 |
| 石像鬼 | 空中/骚扰 | 80/40 | 克制：采集线、落单法师 | 石化形态（落地变高防雕像） |
| 憎恶 | 重型坦克 | 110/70 | 克制：阵地推进 | 瘟疫光环（周围敌人持续掉血） |

> 平衡锚点：单支满编部队（人口 100）造价两族近似；人类单兵质量高 15%~20%，不死补充速度快 25%。

> **实现状态（Phase 1 Demo，V1.2 简化版）**：Demo 未按本表全量实装，而是简化为每族
> **工人 + 步兵/远程/骑兵三类战斗兵**（人类：农夫、步兵、长弓手、骑士；不死：侍僧、骷髅兵、亡灵射手、死亡骑士），
> 循环克制：步兵克骑兵、远程克步兵、骑兵（高移速 7.5）克远程，克制伤害 +50%（`GameConfig.CounterBonus`，出手时乘区生效）；
> 每类兵种由专属兵营生产，三类兵有各自 3D 造型（程序化图元组合）。牧师/狮鹫/石像鬼/憎恶/食尸鬼/亡灵巫师暂移除，
> 特色技能全部待实装。上表 10 兵种为后续版本目标。

### 3.3 建筑与科技（简版，首发规模）

- **人类**：城镇大厅 → 兵营 / 资源收集站 / 弓箭场 / 马厩 / 箭塔 / 民居
- **不死**：大墓地 → 地穴 / 资源收集站 / 诅咒神殿 / 死亡马厩 / 箭塔 / 民居
- **科技两层**：第一层兵种强化（攻防升级），第二层为**AI 指挥科技**（见 5.4）。

> **实现状态（Phase 1 Demo，当前版）**：简化为每族**主基地 + 三座兵种建筑 + 资源收集站/箭塔/民居**——
> 人类：兵营（步兵 + 攻防科技）、弓箭场（长弓手）、马厩（骑士）；
> 不死：地穴（骷髅兵 + 攻防科技）、诅咒神殿（亡灵射手）、死亡马厩（死亡骑士）。
> 旧伐木场改为资源收集站，作为采集加成和远端交付点；所有新建筑由工人施工，施工中生命值逐渐增加且受到双倍伤害。
> 屠宰场、指挥所/通灵塔仍未实装。
> 第一层科技已实装：兵营 / 地穴研究攻防升级（各 2 级，每级 +15%，造价随等级递增，单研究槽、读秒完成）；
> 升级以运行时乘区生效，不改动单位静态数值。建筑与科技全部数据驱动（`BuildingDef` / `TechDef` / `GameConfig`），
> 新增建筑与科技只需加表，不碰逻辑。第二层 AI 指挥科技（5.4）留待指挥所/通灵塔与 LLM 层一并实现。

> **当前对局设置**：开局可选小型/标准/大型地图、资源丰富度和“摧毁主基地/摧毁所有建筑”胜利条件；中央魔法矿富集区鼓励建设资源收集站开分矿，脚本 AI 会判断攻击分矿或主基地。

### 3.4 对战模式（基础）

1. **人机对战**：内置脚本 AI（难度：简单/普通/困难），基于分层行为树。
2. **双人联网对战**：1v1，房间制，支持好友房与匹配。

## 四、技术选型与总体架构

### 4.1 引擎选型论证

| 候选 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| **Unity 2022 LTS（C#）** | RTS 生态成熟（寻路、DOTS 高性能方案、Netcode）、LLM SDK 接入方便、招人容易 | 包体略重 | ✅ **推荐** |
| Godot 4 | 轻量、开源、上手快 | 大规模单位性能与联机方案需自研较多 | 备选（极小团队可议） |
| Cocos / 自研 | — | RTS 生态薄弱，风险高 | 排除 |

**结论：Unity 2022 LTS + URP**。理由：
- 单位寻路与群体移动有成熟方案（A* Pathfinding Project / NavMesh + 局部避障 RVO），百人同屏可用 DOTS/ECS 或对象池 + Job System 优化。
- 网络层有 **Netcode for GameObjects** 与第三方 **Mirror** 可选。
- C# 生态接入 LLM（OpenAI 兼容 API / 国产模型 API）成本最低。

### 4.2 网络同步方案（关键决策）

| 方案 | 说明 | 本项目取舍 |
|---|---|---|
| 帧同步（Lockstep） | 只传指令，状态本地推演，带宽极小，天然支持观战/录像 | 要求严格确定性（定点数、确定性随机），开发调试成本高 |
| 状态同步 | 服务器权威，转发状态 | 单位多带宽大，但容错好、上手快 |

**决策：分阶段实施。**
- **MVP 阶段**：主机权威（Listen Server）+ 状态同步，单位数量控制在每方 100 以内，先跑通双人联机与人机。
- **正式上线前**：评估迁移到"指令同步 + 服务端校验"的混合方案，为锦囊模式的**异步对战**（双方提交策略，服务器模拟裁决）铺路——锦囊模式强制要求服务端可完整跑一局模拟。

### 4.3 总体架构分层

```
┌─────────────────────────────────────────────┐
│ 表现层   Unity 场景/动画/VFX/语音输入 UI       │
├─────────────────────────────────────────────┤
│ 指挥层   自然语言/语音 → LLM 参谋 → 结构化军令 │  ← 本项目核心创新层
│         （Command Schema 校验、指令仲裁）       │
├─────────────────────────────────────────────┤
│ 战术层   执行体 AI（行为树/Utility AI）        │
│         把"军令"拆解为编队、走位、集火微操      │
├─────────────────────────────────────────────┤
│ 模拟层   单位/寻路/战斗/资源/科技（确定性模拟）  │
├─────────────────────────────────────────────┤
│ 网络层   指令同步/状态同步、房间、观战           │
├─────────────────────────────────────────────┤
│ 服务层   LLM 网关（模型路由/降级）、锦囊裁决服   │
│         匹配、存档、抽卡随机数服务               │
└─────────────────────────────────────────────┘
```

**核心设计原则：LLM 永不直接操控单位。** LLM 只产出符合 `Command Schema` 的结构化军令，由战术层执行体负责落地。这样带来三个好处：
1. 指令可校验、可仲裁、可回放（防幻觉、防作弊）；
2. 本地执行体兜底微操，LLM 延迟不致命；
3. 锦囊模式的服务端裁决可以用同一套执行体，不需要为模拟单独开发。

## 五、进阶核心功能设计（AI 指挥体系）

### 5.1 LLM 指挥管线（所有 AI 模式的公共底座）

```
玩家输入（文字/语音）
   ↓ (语音先经 ASR 转写)
[1] 意图解析：LLM 接收「战场态势摘要 + 可用指令集 + 玩家原话」
   ↓
[2] 结构化输出：JSON 军令（function calling / constrained decoding 强约束）
   ↓
[3] 校验与仲裁：Schema 校验 → 合法性校验（兵力够吗？目标存在吗？）
              → 冲突仲裁（与旧命令矛盾时按优先级合并或拒绝并回报）
   ↓
[4] 下发执行体：军团 AI 接收军令，自主完成编队/寻路/微操
   ↓
[5] 回报生成：执行结果摘要回传 LLM，生成自然语言战报反馈给玩家
```

**战场态势摘要（State Digest）**：不喂原始单位列表（token 爆炸），而是喂压缩态势——各军团位置/兵力/血量、资源、敌方可见情报、关键事件（"东侧分矿遭袭"）。目标控制在 1~2K token。

**军令 Schema 示例**：

```json
{
  "orders": [
    {
      "target_force": "第2军团",
      "action": "attack_move",
      "destination": "东侧魔法矿",
      "priority": "high",
      "contingency": "遭遇主力则撤退至桥口",
      "compose_hint": {"坦克": 0.3, "远程": 0.5, "辅助": 0.2}
    }
  ],
  "economy": {"train": ["长弓手", "长弓手"], "expand": false},
  "reply_to_player": "收到，第2军团正在扑向东矿，我会让骑士打头阵。"
}
```

### 5.2 主线模式：自然语言指挥（解决"拼手速"）

- 玩家扮演统帅，**默认不直接框选单位**（保留手动接管开关），通过文字/语音下令：
  - "让一军团守家，二军团带骑士去偷他们东边的矿。"
  - "全线收缩，憋三本出狮鹫。"
- 系统内置**军团编组**：部队按"军团"为单位接受指挥（每军团 10~25 单位），LLM 军令作用于军团，执行体自动分配微操。
- **战报与请示机制**：执行体遇到超预期情况（遇伏、目标消失）时上报，LLM 转述并向玩家请示，形成"指挥—回报—再指挥"的沉浸循环。
- 主线战役 8~10 关，逐步解锁指令类型与军团数量，本身即是教学。

### 5.3 锦囊模式：Prompt 预设策略对战（电子斗蛐蛐）

- 玩家在赛前撰写**策略锦囊**（结构化 Prompt 模板 + 自由文本）：

```
【开局】速双兵营爆骷髅，第4分钟前必须压到对方矿区。
【遭遇战原则】数量劣势>30% 时绝不接战，换家优先。
【资源线】木头低于100停兵补农；魔法矿优先升通灵塔。
【终局触发】敌方主基地血量<50% → 全军总攻。
```

- 双方锦囊 + 随机种子 → **服务器离线模拟裁决**（无需实时在线，异步对战），产出完整录像与战报。
- 竞技循环：天梯排行、锦囊市场（分享/克隆他人策略）、每日镜像地图公平对决。
- 防呆设计：锦囊有字数与指令数上限；服务端做 Prompt 注入防护（锦囊只能引用游戏内概念白名单）。
- **该模式是项目的 UGC 与传播引擎**：天然适合直播、社区"斗蛐蛐"赛事。

### 5.4 AI 指挥科技（核心能力与 AI 挂钩）

以魔法矿为主要消耗的三线科技树（建筑：指挥所/通灵塔）：

| 科技线 | 效果 | 设计意图 |
|---|---|---|
| **传令线** | 提升同时生效的军令槽位（2→3→5）、缩短 LLM 响应延迟 | 指挥带宽 = 科技实力 |
| **参谋线** | 解锁更强的态势感知（战争迷雾内敌军动向推测、战损评估报告、锦囊建议） | 情报质量 = 科技实力 |
| **督战线** | 执行体微操增强（自动拉扯、残血后撤、集火优先级优化） | 基层执行力 = 科技实力 |

> 设计要点：传统 RTS 攀科技 = 数值变强；本项目攀科技 = **你的"AI 军队"变得更聪明**，与经济（魔法矿）争夺形成闭环。

## 六、高阶功能设计

### 6.1 语音辅助指挥

- 管线：麦克风 → ASR（实时转写，支持流式）→ 进入 5.1 指挥管线。
- 定位：**辅助多线调度**。玩家主战场仍可手动/文字精细指挥，语音处理"三线农民拉去西矿""二军团回防"这类支线调度。
- 体验保障：语音指令一律先出文字气泡确认（0.5s 内可取消），关键指令（如全军总攻）要求二次确认；支持全局静音与纯文字模式，保证公平性（双人对战双方同等可用）。

### 6.2 AI 将领模式（语音指挥 AI 队友）

- 玩家作为总司令，麾下 2~3 名 **AI 将领**（各有独立人格与擅长：激进突击型"血斧"、稳重建造型"石心"、骚扰游击型"影鸦"），各自统领一路军团或一片经济区。
- 玩家像联机沟通一样语音分工："血斧你压正面，影鸦去断他采集线，石心把三矿开起来。"
- AI 将领具备**自主性**：会拒绝明显送死的命令（"将军，这是让我去死。"——人格化反馈），会在失联时按自己的风格行动。
- 该模式同时是主线战役的叙事载体与单人内容的主要卖点。

### 6.3 抽卡与随机要素

| 系统 | 内容 | 出现场景 |
|---|---|---|
| **战局随机事件** | "兽潮过境""矿脉暴涌""血月（不死强化夜）"等，每局随机 2~3 个 | 所有对战模式 |
| **统帅卡牌** | 局前构筑 5 张，战中满足条件打出：如"紧急征召（立即+5民兵）""传送卷轴（单军团传送）" | 对战/锦囊模式，带 Ban/Pick |
| **将领成长** | AI 将领随战役获得特质词条（"山地战专家""夜战嗜血"），影响其执行倾向 | 主线/AI 将领模式 |

> 红线：随机要素只影响**战术资源与节奏**，不直接决定数值碾压；天梯模式可勾选"纯净局"（无卡牌无事件）。

### 6.4 双线发展路线：技术线 vs 魔法线

每局对战中，两个种族都可以在**技术线**与**魔法线**之间选择自己的发展路线——路线不由种族锁定，人类可以走魔法，不死也可以走技术。两条路线是**完全不同的玩法体系**：改造兵种形态、解锁独立单位变种、改变军团的作战与指挥方式。

#### 路线概览

| | **技术线（Engineering）** | **魔法线（Arcane）** |
|---|---|---|
| 核心幻想 | 器械、工事、火药与量产强化 | 元素、附魔、仪式与战场法术 |
| 人类风格 | 蒸汽工坊：弩炮、火枪化、要塞工事 | 圣辉秘仪：圣光附魔、圣所结界、天象法术 |
| 不死风格 | 骸骨工坊：白骨构造体、瘟疫投石车、尸爆陷阱 | 深黯秘仪：死灵强化、诅咒领域、幽魂召唤 |
| 资源侧重 | 木头消耗为主（造器械、修工事） | 魔法矿消耗为主（施法、维持结界） |
| 战术画像 | 阵地推进、防御消耗、远程火力 | 爆发控制、战场分割、以质换量 |

#### 路线规则

- **主路线锁定**：对局中达到二本后，在指挥所/通灵塔宣誓路线，**当局不可反悔**——路线选择本身就是核心战略决策（选技术怕被偷矿断矿？选魔法怕被器械平推？）。
- **副线涉猎**：允许解锁对方路线的 1~2 个低级节点作为战术补充（如魔法线偷一门弩炮），但无法获得对方路线的终极能力，保证路线身份感。
- **兵种形态改造**：路线不重做兵种表，而是为现有 10 个兵种各提供 1 个路线变种（如长弓手 → 火枪化"线列枪手" / 附魔"月痕射手"；憎恶 → 构装体"白骨碾压者" / 咒缚"瘟疫使者"），控制制作量的同时让每个兵种有两副面孔。

#### 与 AI 指挥体系的挂钩（本项目特色）

路线不只改数值，还**改变玩家可用的军令词表**——这是与其他 RTS 科技树的本质区别：

| 路线 | 解锁的指挥能力（军令类型） |
|---|---|
| 技术线 | **定点炮击**（"轰击东桥 30 秒"）、**筑垒指令**（"在河谷筑一道临时工事"）、**弹药配给**（指定军团获得一轮强化射击） |
| 魔法线 | **范围传送调度**（"把二军团传送到西矿"）、**战场仪式**（"在桥头布诅咒领域，拖住他们"）、**元素召唤**（临时召唤物支援指定战场） |

即：路线选择决定了 LLM 参谋"听得懂哪些命令"，锦囊模式中也可围绕路线词表撰写策略（"若敌方走魔法线，第 8 分钟后全军散开防传送突袭"），让斗蛐蛐的策略深度成倍增加。

> 平衡锚点：技术线强在正面与续航、弱在机动；魔法线强在爆发与机动、弱在消耗战。两条路线 × 两个种族 = 4 种流派镜像，平衡以"路线对路线的克制三角"（技术克魔法的持久战、魔法克常规的爆发窗、常规兵种克技术的机动骚扰）而非单点数值来调控。

### 7.3 LLM 成本与可用性策略（必须前置考虑）

| 风险 | 对策 |
|---|---|
| 推理成本高 | 指挥层用中小参数模型（军令解析是结构化任务，无需旗舰模型）；态势摘要做增量压缩；单机模式支持本地小模型（7B~14B，消费级显卡可跑） |
| 延迟 | 军令是"低频高价值"操作（5~15 秒一次即可），流式输出 + 执行体自主兜底 |
| 模型服务不可用 | LLM 网关多供应商路由 + **降级方案**：失效时自动切换为预设脚本策略，游戏不中断 |
| 输出不合规 | Constrained decoding / Schema 强校验 + 重试 + 仲裁层拒绝并回报 |

### 7.4 主要风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| LLM 指挥"不可靠"损害核心体验 | 高 | 指挥/执行分层 + 仲裁校验；M0 即建指令正确率测试集持续度量 |
| RTS 模拟层确定性（为锦囊裁决服）难度大 | 高 | M0 预研定点数/确定性方案；若不达标，锦囊模式改"双实例模拟多数裁决" |
| 双族平衡工作量大 | 中 | 兵种克制表先行，自动化对局机器人跑平衡数据 |
| 语音体验不达标（延迟/误识别） | 中 | 文字优先设计，语音为增强项；确认气泡机制兜底 |
| 联网作弊 | 中 | 服务端校验军令合法性；锦囊模式天然服务端权威 |

## 八、成功度量（北极星指标）

1. **指令理解正确率**：LLM 军令解析准确率 ≥ 95%（核心体验的生命线）。
2. **留存**：主线战役次日留存 ≥ 45%；锦囊模式周留存 ≥ 30%。
3. **UGC 活性**：锦囊市场周新增策略数、策略被克隆次数。
4. **对局健康度**：平均对局时长 15~25 分钟；双族胜率差 < 5%。
