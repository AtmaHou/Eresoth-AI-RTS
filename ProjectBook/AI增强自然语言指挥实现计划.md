# Project 咒令：AI 增强与自然语言指挥实现计划

> 文档类型：AI 功能设计、优先级和实施跟踪
> 基线日期：2026-09-06
> 当前基线：Eresoth RTS Phase 1 Demo
> 当前目标：先完成单机文字指挥 MVP，再扩展语音、联机和锦囊模式

## 0. 一页结论

本项目的自然语言价值不在于把“鼠标右键移动”改成一句话，而在于让玩家能够一次表达：

- 多个军团如何分工。
- 部队遇到什么情况应该继续、撤退或改攻。
- 资源、生产、科技和军事如何联动。
- 哪些目标优先，哪些目标禁止攻击。
- 发生突发事件时谁回防、谁继续执行原任务。

因此采用以下原则：

```text
玩家自然语言
    -> 模型只做意图解析
    -> 输出白名单结构化军令
    -> 本地校验、仲裁和执行
    -> 本地战术 AI 负责微操
    -> 事件系统持续回报进度和异常
```

### 推荐技术路线

- Unity 本地负责模拟、军团、战术执行、规则校验和故障降级。
- 独立 AI Gateway 负责模型路由、鉴权、Prompt、结构化输出和日志。
- 第一阶段使用云端快速模型，复杂命令按需升级强模型。
- 本地模型和规则 AI 作为离线/断网降级，不让游戏依赖网络继续运行。
- 保留传统鼠标操作，玩家手动命令可以覆盖自然语言命令。

### 最小有效产品

第一阶段不需要实现全部 50 种操作。最小闭环只需要支持：

1. 给军团下达移动、攻击、防守和撤退命令。
2. 按兵种和目标进行集火、护送和骚扰。
3. 自动处理残血撤退、追击边界和基地告急回防。
4. 自动分配工人、维持生产和研究优先级。
5. 支持“如果……就……”条件命令。
6. 能解释命令为什么成功、失败或被改写。

## 1. 当前代码基线

### 1.1 已有能力

| 能力 | 当前位置 | 可直接复用的价值 |
| --- | --- | --- |
| 单位移动 | `Unit.CommandMove()` | 战术执行层的基础动作 |
| 单位攻击 | `Unit.CommandAttack()` | 统一攻击单位和建筑 |
| 工人采集 | `Worker` / `WorkerAI` | 经济计划的执行基础 |
| 建筑生产 | `Building.TryTrain()` | 生产计划执行基础 |
| 建筑建造 | `Game.BuildAt()` / `Game.BuildStructure()` | 自然语言建设命令基础 |
| 科技研究 | `Building.TryResearch()` | 科技优先级计划基础 |
| 自动反击 | `Unit.lastAttacker` / `NotifyAttacked()` | 本地战术兜底 |
| 编队 | `SelectionManager` | 军团系统的早期原型 |
| 脚本 AI | `EnemyAI` | 资源、生产、出兵规则可迁移 |
| 数据驱动 | `Common.cs` / `GameConfig` | 生成合法单位、建筑和科技词表 |

### 1.2 当前不能直接支撑 AI 的地方

当前系统以“单个单位 + 鼠标输入”为中心，必须补齐：

1. 稳定的 `Force` 军团对象和军团 ID。
2. 单位归属、角色、命令状态和手动接管标志。
3. 资源点、基地、路口、前线等地图语义点。
4. 条件命令、命令生命周期、优先级和撤销。
5. 本地战术执行体，而不是让模型直接操作单位。
6. 战场态势摘要和可见性规则。
7. 事件、战报、失败原因和执行日志。
8. 生产/经济持续计划，而不只是一次点击。
9. API 超时、断网和模型失败时的本地降级。

## 3. 分类后的优先级结论

### P0：快速产生明显效果的最小交付子集

P0 的标准是：不需要复杂兵法模拟，也能明显减少传统 RTS 的多线点击，并且可以在当前 Demo 的移动、攻击、采集、生产、科技基础上落地。

共 25 条：

```text
1, 2, 3, 4, 5, 6, 7, 8,
13, 14, 20, 24, 25,
26, 27, 28, 31, 32, 34,
36, 37, 40, 41, 42, 45
```

实际首个可玩版本建议从其中 12 条开始：

```text
1, 2, 3, 4, 5, 7, 13, 14, 26, 28, 31, 41
```

这 12 条覆盖：移动、攻击、集火、防守、回防、撤退、骚扰、经济、科技和解释，是最小但完整的指挥闭环。

### P1：第二阶段形成“兵法感”

P1 重点是持续条件、局部优势和战场风险管理：诱敌、夹击、动态拆分、生产比例、侦察订阅、敌情推断、时间窗策略和自定义口令。

### P2：长期差异化玩法

P2 包括假动作、总攻触发、策略模板、对比模拟和锦囊模式。这些功能有较高传播价值，但依赖更成熟的军团、地形、可见性、回放和服务端模拟，不应阻塞第一阶段。

## 4. 重新设计后的 AI 总体计划

### 4.1 三层职责

```text
指挥层：理解“想做什么、优先级是什么、什么条件下改变计划”
    玩家文字/语音 -> LLM -> CommandSchema JSON

战术层：决定“由哪些部队、用什么阵型、如何持续执行”
    ForceController / Utility AI / 行为树

模拟层：决定“游戏规则上能否做到，并逐帧执行”
    Game / Unit / Worker / Building
```

绝不能让 LLM 直接修改位置、资源、生命值或胜负状态。它只产出候选军令，真正执行必须经过本地校验。

### 4.2 推荐架构

```text
Unity UI
  -> CommandClient
  -> StateDigestBuilder
  -> AI Gateway
       -> 云端快速模型：普通意图解析
       -> 云端强模型：复杂规划和低置信度请求
       -> 本地模型：离线/故障降级
       -> 规则解析器：最终兜底
  -> CommandValidator
  -> CommandArbiter
  -> OrderDispatcher
  -> ForceController
  -> Unit.CommandMove / Unit.CommandAttack / Worker / Building
```

### 4.3 调用频率和延迟

| 工作 | 执行位置 | 目标 |
| --- | --- | --- |
| 单位移动、攻击、采集 | Unity 本地 | 每帧 |
| 战术重规划 | Unity 本地 | 0.2~2 秒 |
| 普通自然语言命令 | 快速模型 | P95 <= 3 秒 |
| 复杂多军团计划 | 强模型按需 | P95 <= 8 秒 |
| 紧急回防 | 本地规则优先 | <= 300 毫秒 |
| 战报生成 | 异步模型/模板 | 不阻塞执行 |

任何模型请求超时，游戏都应先按旧命令或安全策略继续执行。

## 5. 必须新增的游戏基础设施

### P0：最小闭环所需

#### 5.1 `Force` 军团系统

每个军团至少包含：

```text
id, name, owner, unitIds, role, anchor,
currentOrder, stance, rallyPoint, healthRatio,
manualOverride, lastReportAt
```

单位增加：

- `forceId`
- `unitRole`：前排、远程、骑兵、英雄、工人
- `orderId`
- `manualOverride`
- `commandLockUntil`

第一阶段先支持手动创建军团、自动按兵种编组和军团重组，不急着做复杂的跨军团合并。

#### 5.2 地图语义点

地图生成时注册稳定 ID：

```text
own_main_base, enemy_main_base,
own_east_mana, enemy_west_wood,
center_passage, north_choke,
own_retreat_point, enemy_frontline
```

模型只引用 ID，不输出坐标。自然语言中的“东矿、家门口、北口、敌方主力”由别名解析为语义点或动态目标。

#### 5.3 命令生命周期

所有命令必须支持：

```text
Created -> Validated -> Queued -> Executing
        -> Completed / Failed / Cancelled / Expired / Overridden
```

每条命令保存 `order_id`、来源、优先级、创建时间、过期时间、目标、条件、回退动作和失败原因。

#### 5.4 本地战术执行

P0 只实现：

- 集合和跟随。
- 基础编队和兵种角色分配。
- 集火同一目标。
- 防守半径。
- 追击距离上限。
- 残血撤退。
- 遇袭回防。
- 目标死亡或消失后的重规划。

#### 5.5 经济和生产计划

将单次 `TryTrain()`、`TryResearch()` 扩展为可持续计划：

- 资源目标：木头/魔法矿最低储备。
- 工人配额和资源点优先级。
- 兵种比例和条件停产。
- 建筑顺序。
- 科技优先级。
- 人口和英雄资源保护。

#### 5.6 事件、日志和反馈

统一产生：

```text
EnemySpotted, BaseUnderAttack, ResourceDepleted,
ForceEngaged, ForceRetreated, OrderCompleted,
OrderFailed, BuildingDestroyed, TechCompleted,
TargetLost, ResourceShortage, ManualOverride
```

每个事件要有时间、位置、实体、严重级别和可见范围，支持战报、条件触发和“为什么没执行”。

### P1：兵法能力所需

- 区域防守和巡逻。
- 阵型、侧翼、包围和诱敌点。
- 侦察、战争迷雾和信息过期。
- 目标优先级与禁止目标。
- 动态军团拆分和合并。
- 时间窗和多条件命令。
- 自定义口令、策略模板和命令订阅。
- 更明确的路口、道路、射程区和防御区。

### P2：长期模式所需

- 指挥所/通灵塔与 AI 指挥科技。
- 并行军令槽位和魔法矿消耗。
- 兵种特色技能统一接口。
- 语音和流式 ASR。
- 联机服务端权威校验。
- 锦囊模式服务端离线模拟。
- 完整录像、回放和可复现模拟。

## 6. 命令协议与安全边界

### 6.1 CommandSchema

```json
{
  "schema_version": 1,
  "request_id": "req_001",
  "orders": [
    {
      "order_id": "ord_001",
      "force_id": "army_2",
      "action": "harass",
      "target_id": "enemy_east_mana",
      "unit_filter": ["cavalry"],
      "priority": "high",
      "stance": "cautious",
      "conditions": [
        { "when": "enemy_main_force_seen", "then": "retreat" }
      ],
      "expires_after_seconds": 45,
      "fallback": "retreat_to_own_main_base"
    }
  ],
  "clarification_needed": false,
  "player_reply": "二军团骚扰东矿，发现敌方主力后撤退。"
}
```

首批动作白名单：

```text
move, attack, attack_move, defend, retreat, gather,
harass, escort, scout, focus_fire, regroup, hold,
train, research, build, cancel_order, request_report
```

模型不允许输出任意坐标、任意 C#、资源修改、伤害修改或未注册实体。

### 6.2 校验顺序

```text
JSON Schema
  -> 动作和字段白名单
  -> 实体、目标、视野校验
  -> 兵力、资源、人口、科技校验
  -> 命令冲突和优先级仲裁
  -> 生成本地 Order
  -> 执行并记录结果
```

### 6.3 手动操作优先级

默认优先级：

```text
紧急系统规则 > 玩家手动接管 > 玩家自然语言命令 > 脚本 AI 默认行为
```

手动接管应有持续时间和恢复方式，不能导致军团永久脱离自然语言控制。

## 7. 模型、API 与成本方案

### 7.1 第一阶段选型

| 场景 | 方案 | 作用 |
| --- | --- | --- |
| 默认命令解析 | 云端快速中文指令模型 | 低延迟、低成本、结构化 JSON |
| 复杂战术规划 | 云端强模型按需调用 | 处理多条件和长期目标 |
| 离线/开发 | 本地 7B~14B Instruct 模型 | 无网络和故障降级 |
| 全部失败 | 规则解析器和本地战术 AI | 保证游戏不停 |

供应商通过 Provider 接口接入，优先要求：JSON Schema/Function Calling、中文稳定性、流式输出、超时控制和清晰计费。

### 7.2 AI Gateway

Unity 不保存第三方 API Key，只请求自己的网关：

```http
POST /v1/commands/parse
```

```json
{
  "game_id": "local-session-001",
  "turn": 8420,
  "player_text": "二军团去东矿，遇到主力就撤",
  "state_digest": {},
  "available_actions": ["harass", "retreat"],
  "schema_version": 1
}
```

网关负责模型路由、Prompt 版本、限流、重试、Token 统计、错误日志、敏感信息处理和降级。

### 7.3 StateDigest

不要把完整单位列表发送给模型，只发送压缩态势：

```json
{
  "resources": { "wood": 420, "mana": 180, "population": "62/100" },
  "forces": [
    {
      "id": "army_2",
      "location": "center_passage",
      "composition": { "infantry": 12, "ranged": 8, "cavalry": 3 },
      "health_ratio": 0.92,
      "current_order": "defend"
    }
  ],
  "visible_events": ["东矿在 8 秒前发现敌方侦察"],
  "available_targets": ["enemy_east_mana", "enemy_main_base"]
}
```

默认控制在约 1~2K Token 等价信息量，使用增量事件更新。

## 8. 分阶段实施计划

### F0：可玩语义切片，优先级 P0，约 1 周

**目标**：完全不接模型，先证明 12 条 MVP 命令的 JSON 可以驱动游戏。

实现：

- 新增 `Force`、`ForceManager`、`Order`、`OrderDispatcher`。
- 给单位、建筑、资源点和地图语义点增加稳定 ID。
- 新增命令状态机、错误码和日志。
- 硬编码 JSON 支持 `move`、`attack`、`defend`、`retreat`、`focus_fire`。
- 保留 `Unit.CommandMove()` 和 `Unit.CommandAttack()` 作为底层执行入口。

验收：

- 一军团可以移动、攻击、撤退和重新集结。
- 目标死亡、路径失败、兵力不足时返回可读失败原因。
- 命令可记录、取消和重放。

### F1：本地战术执行 MVP，优先级 P0，约 2~3 周

**目标**：即使没有 API，玩家也能体验自然语言命令背后的明显优势。

实现：

- 军团编成、角色分配和基础阵型。
- 统一集火、护送、骚扰、基地回防。
- 残血撤退、追击边界、敌情触发和目标丢失重规划。
- `SelectionManager` 的编队迁移到 `ForceManager`，保留手动接管。
- `EnemyAI` 的基础行为逐步复用 `OrderDispatcher` 和战术执行接口。

验收：

- 支持命令 1、2、3、4、5、7、13、14 的硬编码结构化输入。
- 100 个单位场景下战术层不造成明显帧率下降。
- API 完全离线时游戏仍可完整进行。

### F2：经济和生产计划，优先级 P0，约 1~2 周

**目标**：让自然语言真正跨越“工人、建筑、资源、科技”多个界面。

实现：

- 工人配额和资源点优先级。
- 资源最低储备、人口保护和英雄资源保护。
- 兵种比例、条件停产和自动补充。
- 建筑顺序和科技优先级计划。
- 将 `TryTrain()`、`TryResearch()` 包装为可持续策略，而不是一次性按钮。

验收：

- 支持命令 26、27、28、31、32、34 的硬编码结构化输入。
- 资源不足时不会出现无穷重试或破坏玩家现有计划。
- 生产计划能被取消、替换并显示当前原因。

### F3：态势摘要、校验和反馈，优先级 P0，约 1~2 周

**目标**：建立模型可安全接入的边界。

实现：

- `StateDigestBuilder` 和可见性过滤。
- JSON Schema 校验、游戏语义校验和命令冲突仲裁。
- `GameEventBus`、`OrderJournal`、失败原因和执行解释。
- 支持命令 36、37、40、41、42、45 的本地模板反馈。
- 事件触发本地回防，不等待模型。

验收：

- 非法目标、不可见目标、资源不足和过期命令全部被拦截。
- 玩家能看到“已执行、部分执行、未执行”的原因。
- 命令日志可以解释某条命令为何被覆盖。

### F4：云端快速模型接入，优先级 P0，约 1~2 周

**目标**：把自然语言解析接入，但不让模型控制执行。

实现：

- 独立 AI Gateway 和 Provider 接口。
- 快速模型只输出 `CommandSchema` JSON。
- Prompt 版本管理、超时、重试、限流、Token 统计和缓存。
- API 失败时切到本地规则解析器和安全策略。
- 先开放 12 条 MVP 命令，其余命令返回“暂不支持”或请求澄清。

验收：

- 核心命令意图正确率 >= 95%。
- JSON Schema 合法率 >= 99%。
- 普通命令 P95 <= 3 秒。
- API 断开后 <= 3 秒切换到本地策略。
- 不合适的命令不会被模型“自作主张”改成危险动作。

### F5：第一阶段文字指挥完整交付，优先级 P0，约 1~2 周

**目标**：完整玩一局“自然语言指挥 vs 脚本 AI”。

实现：

- 指令输入框、确认/追问、历史、撤销和重试。
- 12 条 MVP 命令的自然语言同义表达。
- 执行进度、战报、异常提醒和“为什么没执行”。
- 鼠标操作与自然语言操作并存，手动接管可恢复。

最小交付命令：

```text
移动/骚扰、兵种分工、集火、区域防守、基地回防、
残血撤退、矿区攻击、骑兵切后、工人分配、
资源阈值、科技优先、执行解释
```

验收：

- 不打开多个面板也能完成一局基础经济、进攻、防守和撤退。
- 玩家明确知道军团当前命令、目标、进度和失败原因。
- 自然语言命令相比传统操作减少多线操作步骤，并且没有明显失控。

### F6：兵法战术扩展，优先级 P1，约 3~5 周

开放命令 9、11、12、15、16、17、19、21、23、29、30、33、35、38、39、43、44、46、47、48。

实现：

- 区域、道路、路口和射程区语义。
- 伏击点、夹击、侧翼、诱敌和战线保持。
- 动态军团拆分/合并。
- 侦察订阅、时间窗、多条件策略和自定义口令。
- 更强的阵型和风险评估。

验收：

- 至少 5 条兵法命令能在实战中产生不同于简单攻击的结果。
- 条件触发和撤退边界可重复，不依赖模型随机发挥。
- 复杂命令失败时会局部降级，不会取消所有军团任务。

### F7：高阶 AI 玩法，优先级 P2

开放命令 18、22、49、50，并实现：

- 自定义策略模板和“快攻”等口令。
- AI 指挥科技、并行军令槽位和魔法矿消耗。
- 战术方案对比和简化模拟。
- 语音、AI 将领模式、联机服务端校验和锦囊模式。

这些功能不应阻塞 F5 的自然语言指挥首个可玩版本。

## 9. 测试和评测

### 9.1 三类错误必须分开统计

1. **理解错误**：模型没有理解玩家意图。
2. **校验错误**：非法命令没有拦截，或合法命令被错误拒绝。
3. **执行错误**：命令正确，但军团没有按战术规则完成。

### 9.2 指令测试集

每条 P0 命令至少准备：

- 10 条标准表达。
- 10 条口语表达。
- 5 条省略主语或目标的表达。
- 5 条包含冲突条件的表达。
- 5 条应该追问而不是猜测的表达。

### 9.3 目标指标

| 指标 | F4 目标 | F5/F6 目标 |
| --- | ---: | ---: |
| JSON Schema 合法率 | >= 99% | >= 99.5% |
| P0 意图正确率 | >= 95% | >= 97% |
| 非法命令拦截率 | 100% | 100% |
| 普通命令 P95 | <= 3 秒 | <= 3 秒 |
| 紧急回防响应 | <= 300 毫秒 | <= 300 毫秒 |
| API 故障切换 | <= 3 秒 | <= 2 秒 |
| 执行解释覆盖率 | >= 95% | >= 98% |
| 严重误执行 | 0 | 0 |

## 12. 最终路线图

```text
F0 结构化命令切片
  -> F1 本地军团与战术执行
  -> F2 经济/生产/科技计划
  -> F3 状态摘要、校验、事件和解释
  -> F4 云端快速模型
  -> F5 12 条命令的完整文字指挥 MVP
  -> F6 兵法战术和条件策略
  -> F7 语音、指挥科技、联机和锦囊
```

第一阶段的成功标准不是“模型能说一段漂亮的话”，而是玩家可以用少量自然语言命令稳定完成一局，并且命令结果可预测、可解释、可撤销、可降级。自然语言负责表达指挥意图，本地游戏系统负责规则、执行和最终结果。

## 13. 当前基础玩法实现同步

以下能力已在 Phase 1 基础代码中落地，后续 AI 指挥设计必须以此为准：

- **经济主次**：魔法矿是主要建设、训练和科技资源，木头作为辅助资源；AI 默认优先派工人采集魔法矿。
- **资源收集站**：原“伐木场”改名为资源收集站，`resource_hub` 是可建造的远端交付点，附近工人可以优先把资源交付到该建筑，并获得采集加成。
- **施工系统**：所有玩家/AI 新建建筑都先进入施工状态，由空闲工人自动施工；建筑有施工进度和逐步增长的生命值，施工中受到双倍伤害，并显示工地法阵。
- **生产队列**：所有可生产建筑使用统一的 `GameConfig.MaxProductionQueue` 上限；未完工建筑不能生产、研究或执行防御功能。
- **地图设置**：开局可选小型、标准、大型地图；中央生成高储量魔法矿富集区，资源收集站用于开分矿。
- **AI 分矿**：脚本 AI 会优先建设远端资源收集站，并在攻击阶段根据玩家是否存在分矿选择分矿、前线部队或主基地作为目标。
- **胜利条件**：`MapSettings.victoryMode` 支持“摧毁主基地”和“摧毁所有建筑”两种规则。

### 后续自然语言命令应复用的接口

```text
Game.BuildForwardResourceHub()
Game.AssignBuilders()
Game.NearestDeposit()
Building.constructing / constructionProgress
MapSettings.mapSizeIndex / victoryMode
```

自然语言层不应绕过这些本地规则；例如“去中央矿开分矿”应解析为资源收集站建造计划，由本地选址、资源、工人和施工系统共同验证与执行。
